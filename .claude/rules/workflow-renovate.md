# Renovate: `reusable-renovate.yml` and `renovate.json`

- **`reusable-renovate.yml`** — centralized Renovate runner. Auths via a GitHub App token when `app-id` is set (with `APP_PRIVATE_KEY` secret). Without `app-id` the job fails unless the caller sets `allow-github-token: true`: `GITHUB_TOKEN` cannot open a PR in a repo where Actions may not create pull requests, branches it pushes trigger no CI, and the silent fallback ran as a second Renovate beside the owner-wide App runner while staying green. Scopes targets via `repositories` or `autodiscover`/`autodiscover-filter` inputs (default: the calling repo only). `Build Renovate host rules` writes `RENOVATE_HOST_RULES` to `$GITHUB_ENV` with jq from `env:` (the Renovate step must not set it in its own `env:`, which would override it): a ghcr.io rule for container digest lookups, plus an `api.anthropic.com` rule only when the optional `ANTHROPIC_API_KEY` secret is set. That rule passes the key as `token`, which Renovate sends as `Authorization: Bearer` and redacts from logs, and sends the `anthropic-version` header (`ANTHROPIC_VERSION` in the step's `env:`). It sends no `anthropic-workspace-id`, so the key must be one created for a single workspace: the [API overview](https://platform.claude.com/docs/en/api/overview#authentication) marks that header "required with an API key that isn't scoped to a workspace", so lookups with an org-wide key are expected to fail (#140). Renovate's `applyHostRule` filters the headers of every host rule, global ones included, against `allowedHeaders` (default `["X-*"]`) and drops the rest with a `Disallowed hostRules headers` error, which makes the run exit 1, so the same branch also writes `RENOVATE_ALLOWED_HEADERS=["X-*","anthropic-version"]`; an env value overrides an `allowedHeaders` set in the caller's config file. Unset, the step writes only the ghcr.io rule, byte-identical to the old inline value. `renovate-host-rules` runs the extracted step with the secret unset, set and hostile (#135; the same step as ForumViriumHelsinki/.github#201)
- **`renovate.json`** — this repo's own Renovate config, read by the owner-wide runner on top of its global config, whose default managers (action pins, for example) keep running. It turns on digest pinning for actions (see CLAUDE.md § Conventions) and adds three things. The first is tracking of the Claude model IDs pinned as `workflow_call` input `default:` values: a regex `customManager` over `.github/workflows/*.yml` (prose mentions and dated snapshot IDs are not matched), a `custom.claude-models` datasource reading `GET https://api.anthropic.com/v1/models?limit=1000`, and `regex:^<line>-(?<major>\d+)-(?<minor>\d+)$` versioning per model line, so an Opus pin is only offered Opus IDs. Model updates are grouped as `Claude model IDs`, apart from other dependency updates; a major bump (`5-5` to `6-0`) still gets its own `major-` branch and PR. The lookup needs the runner to pass a workspace-scoped `ANTHROPIC_API_KEY` to `reusable-renovate.yml` (see its entry above); without it each pin carries a "Failed to look up" warning on the Dependency Dashboard and nothing else changes. `renovate-model-pins` checks the manager against the input defaults yq reads, and the versioning per line

  The second is tracking of the two `plugins-ref` input defaults, in `reusable-merge-method.yml` and `reusable-issue-labels.yml` (#109): a regex `customManager` that captures the 40-hex default as `currentDigest` of the `git-refs` package `https://github.com/laurigates/claude-plugins` at `currentValue` `main`. Its `matchStrings` allow only comment, `description:`, `required:` and `type:` lines between `plugins-ref:` and `default:`, so another key there stops the match, and `renovate-plugins-ref` fails. The updates go in their own `claude-plugins plugins-ref` group, scheduled `* * * * 6`: Saturday in the runner's `Europe/Helsinki` timezone, inside the global `* * * * 0,6` branch-creation window that the runner's PRs show. `schedule:weekly` (Monday before 4 AM) would fall outside that window. Two limits:
  - **Every claude-plugins commit is a candidate.** `git-refs` follows the head of `main`, not the two scripts, so the weekly PR moves both pins whether or not `pr-merge-method.py` or `issue-labels.py` changed
  - **A bump is not a no-op to review.** The steps parse the scripts' `KEY=VALUE` output (merge-method: `STATUS`, `METHOD`, `OVERRIDE`, `RULE`, `REASON` and the rest; issue-labels: `REASON=taxonomy_missing:` and the finding types `missing_type` and `missing_routing`), so the PR is merged after re-reading what the scripts emit at the new commit

  `renovate-plugins-ref` reads the regex out of `renovate.json`, applies it to every workflow, and requires the matches to equal the `plugins-ref` defaults yq reads, path by path; fixture blocks pin the quoting and the inputs that must not match. `git-refs` returns no release timestamp, so if the runner's global config sets `minimumReleaseAge` for this datasource, Renovate 43.288.0 (the runner's version) leaves the branch's stability check pending under the default `minimumReleaseAgeBehaviour` `timestamp-required`, and with `prCreation` `not-pending` creates no branch at all; the global config is not in this repository and was not read

  The third is tracking of the four release binaries the reusable workflows download at a pinned version and check against a SHA256 beside it (#166): `GITLEAKS_VERSION` (`gitleaks/gitleaks`), `OSV_SCANNER_VERSION` (`google/osv-scanner`), `OPENCODE_VERSION` (`anomalyco/opencode`) and `RUFF_VERSION` (`astral-sh/ruff`). Each has its own regex `customManager` on the `github-releases` datasource, keyed on the `env:` key name over every workflow, with `depNameTemplate` and `packageNameTemplate` set to the repository and an `extractVersionTemplate` per tag spelling: `vX.Y.Z` for the first three, bare `X.Y.Z` for ruff (its `v`-prefixed tags are the old 0.4.x ones), with pre-release tags rejected. No `packageRule` groups them, so each tool gets its own PR. Renovate cannot write the new `*_SHA256`, so the hash is replaced on each bump PR before it merges: the gitleaks and osv-scanner PRs fail their checksum check until then (`gitleaks-guard` and `osv-scanner-job` run the real install on Linux x86_64), the ruff PR fails `ruff-advisory`'s fixture `ruff_version` check, and the opencode PR is green, because `opencode-review` installs a stub tarball with its own hash; a ruff bump also re-runs `.github/tests/ruff-advisory/gen.sh` (CLAUDE.md, `tool-pins` entry). `renovate-binary-pins` reads each pin with yq from workflow, job and step `env:` and the repository and tag shape from the download URL, then requires exactly one manager per pin with that repository, an `extractVersionTemplate` that turns the URL's tag back into the pin, `semver` versioning, a description that says "fails its checksum check" only for a pin a real-install test covers and "before merging" for the others, and no match in any other workflow. A local `--platform=local --dry-run=extract` with Renovate 43.288.0 extracted exactly these four deps; the lookup needs a GitHub token, so that run skipped it (`github-token-required`), and lookups under the owner-wide runner's token are not verified here. lint.yml's actionlint and ShellCheck pins and the rulesync version stay manual (`tool-pins`)
