# Code-smell workflow: ruff advisory lint

**`reusable-quality-code-smell.yml` reports the Python smells ruff finds deterministically from a shell step, not from Claude** (issue #96, the shape #83 gave the TypeScript workflow). `Ruff advisory lint` (id `ruff`) runs before the analysis, on the changed `.py` files that match `file-patterns` (so the JS/TS default never downloads ruff), and annotates the rule ids in its `RUFF_SELECT`: `C901` (complexity over 10), `PLR0913` (more than 4 parameters, `self`/`cls` not counted), `PLR2004` (a numeric literal other than 0, 1 or -1 in a comparison), `S110`/`S112` (an `except` whose body is only `pass`/`continue`, typed exceptions included), `T201`/`T203` (`print`/`pprint`), `TD003` (a TODO, FIXME or XXX without an issue link) and `ERA001` (commented-out code). Each covers a class the prompt asks Claude for, restricted to Python; nesting depth, boolean flags, duplication and naming stay with Claude, because no ruff rule decides them. The issue's table also proposed ids that are left out, because none decides a class the prompt states (measured with ruff 0.17.4): `PLR0912` counts branches, a threshold the prompt does not have (seven `if`/`else` pairs score 14 branches at complexity 8); `PLR0915` counts statements, not the prompt's lines (a 61-line function whose body is one `return` passes); `BLE001` judges the exception type, not whether the error is swallowed (it flags `except Exception` that reports the error and returns, and not `except ValueError: return None`); `FIX002` flags every TODO, issue link or not; `E741` flags only `l`, `O` and `I`, loop counters included. `T20` is `T201` and `T203`, both selected. The prompt lists exactly these ids as not to report or count in a `.py` file, and `.github/tests/ruff-advisory/run.sh` fails when that list and `RUFF_SELECT` differ, or when the prompt's thresholds differ from the `--config` values the step pins. Three things not to re-derive:
- **`--isolated`, a fixed selection.** The calling repository's ruff configuration is ignored, because the pull request controls it. The command-line `--select` and `--config` already override its `select`, `ignore`, `extend-ignore` and thresholds; measured with ruff 0.17.4, what `--isolated` removes is the lint settings they do not override. Without it, `per-file-ignores`, `extend-per-file-ignores` and `exclude` with `force-exclude` each took a probe file from 18 hits to 0, `pylint.allow-magic-value-types = ["int"]` to 8 (every `PLR2004`), and a `dummy-variable-rgx` matching the arguments to 17 (the `PLR0913`). `# noqa` comments still suppress a hit, as an inline `gitleaks:allow` does in the secrets job. A parse error arrives as `invalid-syntax` and is not reported, since only the selected codes count
- **One exact version, checksum-checked, no `uses:`.** `RUFF_VERSION` and `RUFF_SHA256` change together; the hash is the release's `ruff-x86_64-unknown-linux-gnu.tar.gz.sha256` asset. A mismatch fails the job. A failed download, a ruff exit other than 0 under `--exit-zero` and output that is not JSON arrays are warnings, with ruff's stderr printed between `::stop-commands::` markers because it names files the PR chose. An unreadable pull-request diff range fails, and `workflow_dispatch`/`schedule` with no `HEAD~1` scan nothing, as in `tscritical`
- **Ruff's output is untrusted at the shell boundary.** A path must sit under the checkout and is made relative, the line must be a positive number, annotation text escapes `%`, CR and LF (and `,`/`:` in a property), at most 10 annotations are shown with the rest in the job summary, and `hit_count` is checked to be a number before it reaches `$GITHUB_OUTPUT`. Like `tscritical` it lists the PR's files itself with `git diff -z` and is not narrowed by an incremental re-scan, so a hit in a file Claude no longer sees is still reported on every head

`.github/tests/ruff-advisory/run.sh` runs the extracted step on a scratch repository with a stub `curl` serving a tarball that holds a stub ruff, which replays `ruff-output.json` (output of the pinned release, recorded by `gen.sh`; rerun it after a bump). `issues-found` and `high-severity` still come from Claude, so they no longer count these hits.
